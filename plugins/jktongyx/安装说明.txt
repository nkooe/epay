通用监控码-X转发（jktongyx）

1. 后台刷新支付插件列表，创建支付宝或微信通道并选择“通用监控码-X转发”。
2. 收款码类型选择“二维码”时，收款码地址填写二维码解码后的文本或 URL；选择“图片”时填写图片 URL 或 data:image 数据。
3. 通道配置底部的“配置信息”只是临时工具。平台地址默认当前平台且自动去掉末尾 /，商户 ID 默认 1000，商户密钥留空；填写后生成供监控 App 扫描的 Base64 JSON 二维码。该页面不会保存或记录任何内容。
4. 监控 App 上报地址：POST /api/report/{商户ID}?token={商户V1密钥}。接口使用 URL 中的 token 与该商户的 V1 MD5 密钥进行恒定时间校验，body 里的 sign 允许为空。正文同时兼容两种格式：一是 from、content、timestamp、sign 外层结构（content 为通知 JSON 字符串或对象）；二是 from、package_name、app_name、title、msg、receive_time、device_name 扁平结构。兼容未传 token 但会填写 sign 的客户端，此时按系统 V1 MD5 规则校验全部非空标量字段。
5. 后台测试支付仍使用系统“测试支付收款商户ID”。如使用 1000，请先创建 UID=1000 且使用 V1 MD5 密钥的商户；收银台发现该商户不存在时会显示“请先创建默认的1000商户”。
6. 订单有效期和匹配窗口严格为 5 分钟。支付时间必须晚于下单时间；商户 ID、金额和支付宝/微信支付方式必须全部匹配。同商户、同支付方式、同基础金额的五分钟有效订单按 0.01 递增分配实际金额。
7. “收款码类型”下的“心跳检测”默认关闭。“客户端名称”默认易监控，必须与安卓上报的 client_name 完全一致。开启后，首次收到在线心跳前不可支付；同商户且客户端名称相同的 jktongyx 通道共用心跳，不同名称各自独立，只有开启检测的通道参与判断。App 每 5 秒上报，服务端连续 15 秒没有收到新的有效心跳即判定离线。离线拒绝发起支付，已打开的收银台每 2 秒检查状态、遮挡二维码；恢复在线且订单未过期时恢复显示。后台停用的通道不会被心跳启用，收款上报仍正常处理。

心跳接口：POST /api/report/{商户ID}/heart
api.php 按 client_name 分流：与任一 X 通道配置名称完全一致时只调用 X，其余只调用 PC。无需 X-Report-Plugin 请求头，遗留请求头也不会覆盖名称判断。两个插件可分别独立安装，各自验签和保存状态；选中插件缺失或校验失败时直接报错，不尝试另一个。X 配置名称不能与 PC 正在上报的名称重复（已观察到 PC 的 alipay、wechat），PC 无需配置客户端名称或白名单。停用通道仍保留名称分流，心跳不会将它启用。
安装或升级须同时同步根目录 api.php、includes/lib/ReportHeartbeat.php、plugins/jktongyx/、plugins/jktongypc/jktongypc_plugin.php、admin/ajax_pay.php、includes/lib/AdminApp/Api.php，并刷新插件列表。插件附带的 api.php 用于复制到网站根目录。先更新服务端，确认名称匹配，再移除监控 App 的旧请求头；管理员 App 不需改包。无数据库迁移；升级后等待下一次在线心跳，旧商户级心跳不会继续启用通道。
PC 同用 /heart（GET/POST），channel_id 可选：填写时只更新对应 PC 通道；未填写时仅记录商户与客户端名称的在线信息，不自动启用通道，也不向通道分配 SID。同名微信账号需要 channel_id 才能区分。收款接口各自不变：PC 为 /api/report/{商户ID}/pc，安卓 X 为 /api/report/{商户ID}。
不支持心跳的旧 App 继续使用原收款上报接口，将通道的“心跳检测”保持关闭即可；通道开启检测时必须收到有效在线心跳才能支付。
正文固定四个字段：{"client_name":"易监控","ext_data":"{\"online\":1}","timestamp":1792570048,"sign":"计算得到的MD5"}
client_name 用于插件分流及 X 心跳隔离，不代替验签，也不代表物理设备身份；ext_data 必须是 JSON 字符串，online 为整数 1（在线）或 0（立即离线）。timestamp 支持当前 Unix 秒数（10 位）或毫秒数（13 位），参与签名时必须使用实际发送的原始数值，服务端验签后统一为秒判断。上报时间必须在最近 15 秒内，最多允许快于服务器 5 秒。重复、旧时间戳不续期，同一秒内离线优先。
sign 必须校验：正文排除 sign 后按字段名升序拼接 key=value，以 & 连接，直接追加 URL 中该商户的 V1 MD5 密钥，使用 UTF-8 计算 32 位小写 MD5。示例原文：client_name=易监控&ext_data={"online":1}&timestamp=1792570048商户密钥。ext_data 使用实际字符串，不包含外层 JSON 的转义反斜杠；心跳不接受 token 替代签名。
成功响应：{"code":200,"message":"成功","data":{},"redirect":""}。App 需确认 HTTP 成功且 code=200，不积压或重试旧心跳。心跳代表 App 收款监听可用，不能证明支付宝或微信账号仍登录。

收款通知严格校验（2026-10-24）：
package_name 必须为微信 com.tencent.mm，或支付宝 com.eg.android.AlipayGphone；未知包名、企业微信以及仅提供 app_name 的通知均拒绝，不再根据正文猜测支付方式。
微信 title 完整匹配：微信收款助手、微信支付收款、二维码赞赏到账、店员消息、收款单到账、个人收款码到账、收款通知、微信收款商业版、对外收款。
支付宝 title 完整匹配：支付宝、收钱码、店员通、已转入余额、你已成功收款、通过扫码向你付款、成功收款。标题前后加字、空白不匹配。
msg 必须完整匹配对应支付方式的收款模板；金额为正数，最多两位小数，不从 title 提取金额。微信真实样本“微信支付收款0.10元(朋友到店)”及不带该后缀的正文均支持。支付宝正文须明确为“通过扫码向你付款0.10元”或“你已成功收款0.10元”这类收款模板，不能仅有“已转入余额10元”。
聊天前缀、引用、追加文字、换行、多个金额和未知模板均拒绝；不自动截取或补全文案。标题属于白名单不代表正文可以随意填写。该规则用于减少通知误识别，不是支付机构的到账核验。
